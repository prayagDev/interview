Ques: Why we call the heap as private heap when we talk about python memory?
Ans:
    because only the Python memory manager (PyMalloc/CPython) can directly allocate or free that memory.
    Your Python code never manipulates the heap directly
    it only creates references to objects,
    while Python manages the heap behind the scenes.

    x = 100
    x ───────────────┐

                 ▼
        +----------------+

        +----------------+

                 │
    y ───────────────┘
                 │
                 ▼

    Line 3
    a = x

                 │
y ───────────────┤
                 │
a ───────────────┘
                 │
Heap             ▼
        +----------------+
        | int(100)       |
        | refcount = 3   |
        +----------------+


    Line 4
    a = ""

    x ───────────────┐
                 │
y ───────────────┘
                 │
                 ▼
        +----------------+
        | int(100)       |

        +----------------+

a ───────────────┐
                 │
Heap             ▼
        +----------------+
        | ""             |

    Line 5
    a = "one hundred"


    x ───────────────┐

    which object ref count becomes 0 it becomes eligible for free memory



Ques: What is cicular reference? why we need garbage collector for this case? why cannot we cleanup using reference counting?
Ans:
    class Node: pass a = Node() b = Node() a.friend = b b.friend = a
    del a 
    del b 

    so here del only deletes Namespace not objects
    the reason is simple object will not delete because it still reference to another object which still alive

    so we use garbage collector which finally clean up this stuff
